Decorator reference

Every NestJS 12 decorator grouped by kind — modules and classes, route methods, parameters, enhancer binding, OpenAPI, microservices and WebSockets — each with its package and what it does.

CurrentUpdated 2026-09-11·NestJS Migration and Reference

Every decorator below was read from the published type declarations of @nestjs/common@12.0.1, @nestjs/core@12.0.1, @nestjs/platform-express@12.0.1, @nestjs/swagger@12.0.1, @nestjs/microservices@12.0.1 and @nestjs/websockets@12.0.1. Nothing is listed that is not exported by one of those packages. Import paths are the package root in every case — Nest does not publish deep decorator paths for you to import from.

#Modules and classes

All from @nestjs/common unless noted.

DecoratorApplies toWhat it does
@Module(metadata)classDeclares a module: imports, controllers, providers, exports.
@Global()classMakes the module's exported providers available everywhere without importing it. Use sparingly.
@Injectable(options?)classMarks a class as resolvable by the container. options carries scope and durable.
@Controller()classRegisters the class as a controller with no path prefix.
@Controller(prefix)classPrefix as a string or string[].
@Controller(options)class{ path, host, version, scope, durable }.
@Inject(token?)constructor param, propertyInjects by an explicit token instead of by type — for strings, symbols, and forwardRef().
@Optional()constructor param, propertyResolution failure yields undefined instead of throwing.
@Catch(...exceptions)classMarks an exception filter and narrows it to the listed exception types. No arguments means "catch everything".
@SetMetadata(key, value)class, methodAttaches arbitrary metadata, read back with Reflector. The building block of every custom @Roles()-style decorator.
@Dependencies(...tokens)classDeclares constructor dependencies explicitly. For plain JavaScript projects, where no type metadata is emitted.
@Bind(...decorators)methodApplies parameter decorators to a method positionally. Also a plain-JavaScript affordance.

Two helper functions live alongside them and are not decorators themselves:

FunctionPackageWhat it does
applyDecorators(...decorators)@nestjs/commonComposes several decorators into one reusable decorator.
mixin(class)@nestjs/commonRegisters a dynamically generated class so the container can resolve it — the pattern behind parameterized guards and interceptors.

#Route methods

All from @nestjs/common. Every one takes path?: string | string[] — there is no RegExp overload.

DecoratorHTTP method
@Get(path?)GET
@Post(path?)POST
@Put(path?)PUT
@Patch(path?)PATCH
@Delete(path?)DELETE
@Head(path?)HEAD
@Options(path?)OPTIONS
@All(path?)every method
@Search(path?)SEARCH
@QueryMethod(path?)QUERY — named this way to avoid clashing with the @Query() parameter decorator
@Propfind(path?)PROPFIND (WebDAV)
@Proppatch(path?)PROPPATCH (WebDAV)
@Mkcol(path?)MKCOL (WebDAV)
@Copy(path?)COPY (WebDAV)
@Move(path?)MOVE (WebDAV)
@Lock(path?)LOCK (WebDAV)
@Unlock(path?)UNLOCK (WebDAV)
@RequestMapping(metadata?)the underlying factory: { path, method }

#Response shaping on the handler

DecoratorApplies toWhat it does
@HttpCode(statusCode)methodSets the success status. POST defaults to 201, everything else to 200.
@Header(name, value)methodSets a response header. value may be a () => string evaluated per response.
@Redirect(url?, statusCode?)methodRedirects. Note the order — URL first, status second — which is the opposite of Express 5's res.redirect().
@Render(template)methodRenders a view with the handler's return value as the locals. Needs setViewEngine().
@Sse(path?, options?)methodTurns the handler into a Server-Sent Events stream; return an Observable<MessageEvent>.
@Version(version)methodThe route's version, for enableVersioning().

#Parameters

All from @nestjs/common. Every one of @Param(), @Query(), @Body(), @RawBody() and @Headers() has overloads taking a property name, a list of pipes, or a ParameterDecoratorOptions object — { schema?, pipes? }, where schema is any Standard Schema.

DecoratorYields
@Req() / @Request()the platform request object (Express Request under @nestjs/platform-express)
@Res(options?) / @Response(options?)the platform response object. { passthrough: true } keeps Nest's response pipeline; the default false opts out of it entirely
@Next()the platform next function
@Param(name?, …)route parameters, or one of them
@Query(name?, …)query-string values, or one of them
@Body(name?, …)the parsed request body, or one property of it
@RawBody(…)the untouched body Buffer. Requires the app created with { rawBody: true }
@Headers(name?)request headers, or one of them
@Ip()req.ip, which honors the trust proxy setting
@Session()req.session, populated by session middleware you mounted
@HostParam(name?)parameters captured from @Controller({ host })
@UploadedFile(fileKey?, …pipes)one uploaded file, paired with FileInterceptor
@UploadedFiles(…pipes)several uploaded files, paired with FilesInterceptor or FileFieldsInterceptor
@SseSignal()the AbortSignal for an SSE response's lifetime — aborted when the client disconnects, the stream completes, or it errors

createParamDecorator(factory, enhancers?) from @nestjs/common builds your own. It is the mechanism behind every @CurrentUser() in every Nest codebase — see Custom decorators.

#File upload interceptors

These are interceptor factories from @nestjs/platform-express, used inside @UseInterceptors(), and they are what make @UploadedFile() and @UploadedFiles() produce anything. They wrap multer 2.2.0, which the platform package pins.

FactoryWhat it accepts
FileInterceptor(fieldName, options?)one file on one field
FilesInterceptor(fieldName, maxCount?, options?)several files on one field
FileFieldsInterceptor(uploadFields, options?)several named fields, each with its own maxCount
AnyFilesInterceptor(options?)every file on any field
NoFilesInterceptor(options?)no files — rejects a multipart request that carries any

#Binding guards, interceptors, pipes and filters

All from @nestjs/common. Each accepts classes (so the container instantiates and injects them) or already-constructed instances.

DecoratorApplies toBinds
@UseGuards(...guards)class, methodCanActivate implementations — authorization, authentication, throttling
@UseInterceptors(...interceptors)class, methodNestInterceptor implementations — caching, timeouts, serialization, file uploads
@UsePipes(...pipes)class, methodPipeTransform implementations, applied to every parameter of the handler
@UseFilters(...filters)class, methodExceptionFilter implementations
@SerializeOptions(options)class, methodOptions for ClassSerializerInterceptor (groups, excludeExtraneousValues, …) or for StandardSchemaSerializerInterceptor ({ schema, validateOptions })

Within each stage, narrower wins later: global → controller → method. Nothing above registers a global enhancer; that is app.useGlobalGuards() and friends, or the injection tokens from @nestjs/core:

TokenPackageRegisters
APP_GUARD@nestjs/corea global guard that can inject dependencies
APP_INTERCEPTOR@nestjs/corea global interceptor
APP_PIPE@nestjs/corea global pipe
APP_FILTER@nestjs/corea global exception filter

#Microservices

All from @nestjs/microservices (12.0.1).

DecoratorApplies toWhat it does
@MessagePattern(pattern, transport?, extras?)methodHandles a request-response message matching the pattern.
@EventPattern(pattern, transport?, extras?)methodHandles a fire-and-forget event. No response is sent.
@Payload(property?, …)parameterThe message payload, or one property of it. Takes pipes and ParameterDecoratorOptions like @Body().
@Ctx()parameterThe transport-specific context object — RmqContext, KafkaContext, NatsContext and friends.
@Client(metadata?)propertyInjects a ClientProxy built from the given ClientOptions.
@GrpcMethod(service?, method?)methodHandles a unary gRPC call.
@GrpcStreamMethod(service?, method?)methodHandles a gRPC stream as an RxJS Observable.
@GrpcStreamCall(service?, method?)methodHandles a gRPC stream as the raw call object.
@GrpcService(…)classA gRPC service controller — an alias of @Controller().

Note

NestJS 12's NATS transport is built against @nats-io/transport-node 3.4.0, and custom deserializers now receive the full NATS message object — read the payload with msg.json(). See NestJS 11 → 12 migration.

#WebSockets

All from @nestjs/websockets (12.0.1), used with a platform adapter such as @nestjs/platform-socket.io (12.0.1).

DecoratorApplies toWhat it does
@WebSocketGateway(port?, options?)classDeclares a gateway. Also accepts a single options object.
@WebSocketServer()propertyInjects the underlying server instance.
@SubscribeMessage(message)methodHandles one named client message.
@MessageBody(property?, …)parameterThe message payload, or one property of it. Takes pipes and ParameterDecoratorOptions.
@ConnectedSocket()parameterThe client socket the message arrived on.
@Ack()parameterThe acknowledgement callback, for clients that send one.

See WebSockets.

#Common mistakes

  • Using @Query() as a route method. The QUERY HTTP method decorator is @QueryMethod(); @Query() reads the query string.
  • Injecting @Res() and returning a value. The return value is discarded and the request hangs. @Res({ passthrough: true }) is almost always what you meant.
  • Expecting @SetMetadata() to do something on its own. It only attaches metadata; a guard or interceptor has to read it with Reflector.
  • Reaching for @UsePipes() to validate one parameter. It applies to every parameter of the handler. Put the pipe on the parameter instead.
  • Using @Global() to avoid writing imports. It makes the module graph unreadable and hides real coupling.
  • Assuming a route decorator takes a RegExp. None of them does. Match loosely and validate in a pipe.
  • Using @RawBody() without { rawBody: true }. It yields undefined, silently.
